초안 모드를 실행한다. 인자: $ARGUMENTS

발행은 하지 않는다. 초안 파일만 만든다. 네이버 블로그 발행은 사용자가 직접 한다.

## 준비 (순서대로)
1. 인자를 `<플랫폼> <문제번호> [풀이파일]`로 읽는다. 형식이 맞지 않으면 사용법만 알려 주고 멈춘다.
2. 문제 데이터 `problems/<플랫폼>/<번호>.json`을 읽는다. 없으면 `/learn`과 같은 방법으로 준비한다.
3. 풀이 코드를 찾는다. 파일이 인자로 주어지면 그것을 쓰고, 아니면 `solutions/<플랫폼>/`에서 문제 번호가 들어간 파일을 찾는다. 풀이 코드가 없으면 **초안을 만들지 말고** 풀이 파일 위치를 알려 달라고 한다.
4. 있으면 읽는다: `problems/<플랫폼>/<번호>.learn.md`(개념 정리), `problems/<플랫폼>/<번호>.coach.md`(시도한 내용과 막힌 지점).
5. `drafts/<플랫폼>-<번호>.md`가 이미 있으면 덮어쓰지 말고 사용자에게 물어본다.

## 먼저 검증한다 (글을 쓰기 전)
1. 풀이 코드를 읽고 **버그, 놓친 경계 조건, 비효율**이 있는지 확인한다. 있으면 글을 쓰지 말고 먼저 사용자에게 알려 준다. 고칠지 그대로 쓸지 사용자가 정한다.
2. 가능하면 문제의 예제 입력으로 코드를 실행해서 결과를 확인한다. (Java는 `javac`/`java`, C++은 `g++`를 쓴다. 실행하지 못했으면 글에도 "예제 실행은 확인하지 않았다"고 표시한다.)
3. 시간복잡도와 공간복잡도는 코드를 실제로 보고 계산한다. 추측으로 쓰지 않는다. 근거 한 줄을 함께 적는다.

## 사용자의 생각을 지어내지 않는다
"접근 방법"의 **처음 떠올린 생각**과 **막힌 지점**은 `.coach.md`에 사용자가 직접 말한 내용에서만 가져온다. 그 기록이 없거나 부족하면, 지어서 채우지 말고 사용자에게 먼저 물어본다.
"처음에 어떻게 접근하려 했는지, 어디서 막혔는지, 어떻게 해결했는지 짧게 알려 줘. 기억나는 만큼만 말해도 돼."
사용자가 답하지 않으면 해당 부분은 비워 두고 "(직접 채우기)"라고 표시한다.
힌트를 몇 단계까지 봤는지, 해설을 봤는지도 기록에 있으면 솔직하게 반영한다. 해설을 봤다면 "해설을 보고 이해했다"고 쓴다. 혼자 풀었다고 쓰지 않는다.

## 글의 구조 (이 순서와 제목을 쓴다)
1. 제목: `[플랫폼] 문제번호 문제이름 (언어/알고리즘 유형)` — 맨 위 `# ` 제목 한 줄
2. `## 문제 요약`: 직접 쓴 한두 줄 요약과 문제 링크
3. `## 난이도 / 알고리즘 태그`
4. `## 접근 방법`: 처음 떠올린 생각 → 막힌 지점 → 해결한 아이디어
5. `## 사용한 개념 정리`: 처음 보는 사람도 이해할 수준으로 짧게. `.learn.md`를 바탕으로 하되 그대로 복사하지 말고 글에 맞게 줄인다.
6. `## 풀이 코드`: 핵심 부분에 주석
7. `## 시간복잡도 / 공간복잡도`: 근거 한 줄과 함께
8. `## 배운 점 / 비슷한 문제`: 배운 점과 비슷한 문제 2~3개 (실제 있는 문제만. 번호를 확신하지 못하면 유형만 적고 "번호 확인 필요"로 표시한다.)

## 규칙
- **저작권**: 문제 원문(지문, 예제 입출력)을 그대로 복사하지 않는다. 링크, 문제 번호, 제목과 직접 쓴 한두 줄 요약만 넣는다.
- **문체**: 일기체 평어체로 쓴다. 종결은 "~했다", "~였다", "~이다". 문장 부호는 줄이고 `!`, `?`, `ㅎㅎ`, `~`는 꼭 필요할 때만 쓴다. 이모지는 쓰지 않는다. 과장과 광고성 문구를 쓰지 않는다. "이번 포스팅에서는 ~에 대해 알아보겠습니다" 같은 상투적 문구를 피한다.
- **가독성**: 문단은 2~4줄로 짧게 끊는다. 모바일 열람이 많다.
- **목록**: 중첩 목록은 2단계까지만 쓴다. 하위 항목은 **4칸 들여쓰기**로 쓴다. (렌더러가 2칸 들여쓰기를 중첩으로 읽지 못한다.)
- **코드 블록**: 언어를 명시한 펜스 코드 블록으로 쓰고, 한 블록은 50줄 이내로 한다. 길면 핵심 부분만 보여 준다.
- **정확성**: 확실하지 않은 내용은 지어내지 말고 "확인 필요"로 표시한다.
- 독자는 비슷한 입문자일 수 있다. 용어는 처음 나올 때 쉬운 말로 풀어 준다.

## 저장과 마무리
1. `drafts/<플랫폼>-<번호>.md`에 저장한다.
2. `.venv/bin/python src/render_draft.py drafts/<플랫폼>-<번호>.md`를 실행해 HTML을 만든다. 브라우저가 열린다.
3. 사용자에게 알려 줄 것
    - 만든 파일 위치
    - 검증 결과 (예제 실행 여부, 시간복잡도 근거, 발견한 문제)
    - "확인 필요"나 "(직접 채우기)"로 남긴 부분
    - 붙여넣는 방법: 브라우저에서 전체 선택(Cmd+A), 복사(Cmd+C), 네이버 글쓰기 화면에 붙여넣기(Cmd+V). 붙여 넣은 뒤 **코드 블록 모양과 줄바꿈을 눈으로 확인**하고, 깨지면 네이버 에디터의 코드 서식으로 다시 넣도록 안내한다.
4. 발행은 사용자가 직접 한다고 한 번만 상기시킨다.
