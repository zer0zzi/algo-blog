학습 모드를 실행한다. 인자: $ARGUMENTS

## 순서
1. 인자를 `<플랫폼> <문제번호>`로 해석한다. 형식이 맞지 않으면 사용법만 알려 주고 멈춘다.
2. 문제 데이터 `problems/<플랫폼>/<번호>.json`을 읽는다.
   - 파일이 없고 플랫폼이 `boj`면 `.venv/bin/python src/boj.py <번호>`로 1개만 가져온다.
   - 파일이 없고 플랫폼이 `programmers`면 `.venv/bin/python src/programmers.py add <번호>`를 실행해서 템플릿을 만들고, 사용자에게 내용을 채워 달라고 안내한 뒤 멈춘다.
3. `problems/<플랫폼>/<번호>.learn.md`가 이미 있고 `--force`가 없으면, 새로 만들지 말고 그 내용을 보여 준다.
4. 아래 규칙으로 분석해서 `.learn.md`에 저장하고, 같은 내용을 사용자에게 보여 준다.

## 독자 수준
- 독자는 알고리즘 개념을 거의 모르는 입문자다. 이 도구와 문제만으로 공부한다. 따로 공부한 것이 없다고 가정한다.
- 용어는 처음 나올 때 한 번 쉬운 말로 풀어서 설명한다. (예: "나머지 연산 = 시계처럼 한 바퀴 돌면 처음으로 돌아오는 계산")
- 개념마다 일상 속 비유 한 가지와, 숫자가 작은 예시(손으로 따라갈 수 있는 크기)를 넣는다.
- 한 문단은 2~3문장으로 짧게 쓴다. 수식과 약어(LCM, CRT 등)는 풀어 쓴 말을 먼저 쓰고 약어는 괄호로 덧붙인다.
- 이 문제를 풀기 위해 먼저 알아야 할 기초가 있으면 "먼저 알아야 할 기초"에 쉬운 것부터 순서대로 적는다.
- 어려운 개념(예: 중국인의 나머지 정리)은 "더 공부할 것"으로만 이름과 한 줄 설명을 붙이고, 이 문제에서 필수가 아니면 깊게 다루지 않는다.

## 분석 규칙
- 이 분석은 **풀이 전에 읽는다.** 정답 코드, 단계별 풀이, 정답 자체를 쓰지 않는다. 개념과 유형 수준에서만 설명한다. 이 문제에 곧바로 쓰는 방법은 한 단계 추상화해서 말한다. 구체적인 힌트는 코치 모드의 몫이다.
- 시간복잡도는 제한사항의 숫자(N, 시간 제한)를 근거로 계산해서 쓴다. 추측으로 쓰지 않는다.
- 확실하지 않은 내용은 지어내지 않고 "확인 필요"로 표시한다.
- JSON의 `tags`가 비어 있으면 알고리즘 유형을 추정하고 "추정값, 확인 필요"로 표시한다.
- JSON의 `omitted_images`가 있고 입출력 예 설명이 이미지에 의존해 보이면 "이미지 내용 확인 필요"로 표시한다.
- 문제 원문(지문, 예제)을 그대로 옮겨 쓰지 않는다. 직접 쓴 표현으로 요약한다.
- 문체는 일기체 평어체(~이다, ~한다)로 간결하게 쓴다.
